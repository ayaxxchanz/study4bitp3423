The central exam argument

Enterprise Architecture (EA) is a whole-organisation view connecting business goals, processes, information, applications and technology. It helps decisions work together rather than allowing each department to optimise its own system in isolation.

1 · See the whole

Connect business, data, applications and technology.

2 · Explain dependencies

Show how a change in one layer affects the others.

3 · Prove alignment

Trace IT decisions to business outcomes and feedback.

01Slides 2–5

What is EA?

  • Whole-organisation view of goals, processes, data, apps, tech
  • Five university systems may work separately but fail together
  • EA exposes dependencies and supports coordinated decisions

↳ Whole view, not just an IT diagram.

02Slides 2–5, 17

Why organisations need EA

  • Duplication: departments build overlapping systems
  • Disconnected data: inconsistent student information
  • Costly change: many systems need coordinated updates
  • Result: manual re-entry, delays and unreliable reports

↳ Local optimisation can create enterprise failure.

03Slides 6–8

Frameworks

  • TOGAF: process-oriented; Architecture Development Method
  • Zachman: classification-oriented; different viewpoints
  • FEAF, DoDAF, MODAF are other examples
  • A framework organises EA work; it is not the EA itself

↳ TOGAF = HOW; Zachman = WHAT views.

04Slides 9–10, 14

Business architecture

  • Goals, capabilities, workflows, roles and accountability
  • University: admission → enrolment → graduation
  • Clarify registration rules and responsibilities first
  • Automating a bad process makes confusion faster

↳ Question: what must the organisation do?

LECTURE 3 · CORE IDEABusiness ↔ Data ↔ Applications ↔ Technology↓ 8 recall branches
05Slides 11, 14

Data architecture

  • Definitions, meaning, ownership and exchange of information
  • Student ID, prerequisites, programme, fees and seat counts
  • Choose authoritative source of truth
  • Shared APIs cannot fix inconsistent data meaning

↳ Question: which information is trustworthy?

06Slides 12, 14

Application architecture

  • Systems, their functions and how they communicate
  • Registration, student record, LMS and finance need integration
  • Avoid duplicated functions and unreliable status updates
  • Define interfaces and dependencies between applications

↳ Question: which systems interact?

07Slides 13–14, 18

Technology architecture

  • Hosting, networks, databases, cloud, devices and security
  • Support peak enrolment load, availability and recovery
  • Capacity and access control support the applications
  • A platform choice is one part of the full architecture

↳ Question: what infrastructure supports the service?

08Slides 15–20

Alignment + selection

  • Goal → architecture → delivery → feedback
  • Example: faster registration → connected status → fewer corrections
  • Select for business fit, lifecycle cost, integration & skills
  • Alignment is continuous, not a single sign-off

↳ If IT creates no business value, revisit it.

Structured Exam Practice

Past-paper style: a short scenario, numbered subquestions and specific mark allocations. Answer point-by-point, not as a long essay.

How to answer a structured question

Check the command word (state, identify, explain, discuss, justify), the number of items requested and the allocated marks. For 4 marks, aim for two distinct explained points; for 6 marks, explain three. For a case study, use the facts in the scenario.
